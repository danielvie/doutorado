4 · Solving the LMI in MATLAB

Three modelling layers, and how to verify the result

The LMI is the same in every case; only the modelling layer differs. All three routes below were run on the pair from §3.

4.1  YALMIP with a conic solver

The one this repository uses, in scripts/generate_results.m and in studies/lyapunov/generic_example.m. You write the inequalities the way you would write them on paper, and YALMIP compiles them for whichever solver is on the path.

function [P, decrease] = common_lyapunov(A)
n = size(A{1}, 1);
P_var = sdpvar(n, n, 'symmetric');
t     = sdpvar(1);

constraints = [P_var >= 1e-8*eye(n), trace(P_var) == n, t >= 0];
for i = 1:numel(A)
    constraints = [constraints, A{i}'*P_var*A{i} - P_var <= -t*eye(n)];
end

diagnostics = optimize(constraints, -t, ...
    sdpsettings('solver', 'sedumi', 'verbose', 0, 'sedumi.eps', 1e-9));
if diagnostics.problem ~= 0
    error('common_lyapunov:infeasible', '%s', diagnostics.info);
end

P = value(P_var);
P = (P + P')/2;                     % kill the asymmetry the solver leaves behind
decrease = value(t);

Three implementation details that matter

trace(P) == n bounds the problem. Without it, maximising t is unbounded, and solvers respond to that by returning nonsense or by failing in a way that looks like infeasibility.

P = (P + P')/2 after value(). The returned matrix is symmetric only to solver tolerance, and an unsymmetrised P makes every later eigenvalue test slightly wrong.

Check diagnostics.problem and fail loudly. Code that keeps going after an infeasible solve will quietly compute a “certificate” from garbage.

4.2  The Robust Control Toolbox LMI Lab

If YALMIP is not available, the Robust Control Toolbox ships an LMI parser. It is older and much more verbose. Each term of each inequality is declared separately, and the sign convention takes a moment to internalise. But it needs nothing beyond MATLAB.

setlmis([]);
P = lmivar(1, [2 1]);              % one full symmetric 2x2 block
lmiterm([-1 1 1 P], 1, 1);         % LMI 1:  P > I
lmiterm([ 1 1 1 0], 1);
lmiterm([ 2 1 1 P], A1', A1);       % LMI 2:  A1'*P*A1 - P < 0
lmiterm([-2 1 1 P], 1, 1);
lmiterm([ 3 1 1 P], A2', A2);       % LMI 3:  A2'*P*A2 - P < 0
lmiterm([-3 1 1 P], 1, 1);
problem = getlmis;
[tmin, xfeas] = feasp(problem);      % feasible when tmin < 0
Pv = dec2mat(problem, xfeas, P);
Result:  best value of t:   -0.101082

A different P, and a worse contraction factor: 0.9681 against 0.9149. Both are correct. feasp stops as soon as it is inside the feasible set, while the YALMIP program above pushes for the largest decrease margin. If all you need is a yes/no answer, stopping early is fine. If you are going to quote a convergence rate, ask for the margin.

4.3  CVX

Closest to the mathematical notation of the three. Requires CVX to be installed; it is not on this machine, so unlike the two above this snippet is written from the API rather than from a run.

cvx_begin sdp quiet
    variable P(n, n) symmetric
    variable t
    maximize(t)
    subject to
        P - 1e-8*eye(n) >= 0;
        trace(P) == n;
        for i = 1:numel(A)
            P - A{i}'*P*A{i} - t*eye(n) >= 0;
        end
cvx_end

4.4  Verifying the certificate independently of the solver

A conic solver returns an approximate solution to a tolerance. Near the boundary of the feasible set, which is where the interesting cases sit and where the paper’s own certificate sits, that tolerance can be the difference between a proof and a wrong claim. The certificate is cheap to re-check independently, so re-check it. Four lines:

P = (P + P')/2;                                  % symmetrise first
assert(min(eig(P)) > 0)                          % P really is positive definite
for i = 1:numel(A)
    S = P - A{i}'*P*A{i};  S = (S + S')/2;
    assert(min(eig(S)) > 0)                      % strict decrease, with a margin
    q(i) = sqrt(max(real(eig(A{i}'*P*A{i}, P))));   % the contraction factor
end

The generalised eigenvalue call is worth a note. ‖A‖P2 is the largest λ with AₜPA v = λPv, which eig(A'*P*A, P) computes directly, with no Cholesky factor to form and no explicit inverse. Take real of the result: the pencil is symmetric so the eigenvalues are real, but rounding can leave imaginary parts of order 10−16 that will otherwise contaminate a max.

Two numerical failure modes

A margin that is only numerically positive. If min(eig(P - A'PA)) comes back at 10−11, you do not have a proof, you have a solver artefact. The certificate in §5 has margin 9.7×10−5 with a contraction factor of {{paper.q0|.6f}}. That is close to the boundary, but comfortably above the noise floor, and the paper says so rather than rounding it to 1.

A badly conditioned P. cond(P) is how eccentric the ellipsoid is. The certificate in §5 has cond(P) = {{paper.condP|.0f}}, which is fine for a proof but means ‖e‖P and ‖e‖2 can differ by a factor of {{paper.condsqrt|.0f}}. Never quote one while thinking about the other.
