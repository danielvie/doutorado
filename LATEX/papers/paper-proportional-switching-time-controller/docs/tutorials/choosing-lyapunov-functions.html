LYAPUNOV METHODS · ONE EXAMPLE, THREE ROUTES

Three Ways to Find V

A Lyapunov function is a scalar that only falls. The theory says what it must satisfy; it does not say where to get one. This is a worked tour of the three places people actually get one from — physics, a matrix equation, and a solver — on a single running example.

00

The example, and the plan

Everything below runs on one system, small enough to check by hand and rich enough to break every method in an instructive way: a mass on a spring with a damper.

m q̈ + c q̇ + k q = 0,     m = 1,  k = 4,  c = 0.4

Take the state to be position and speed, x = [q ; v] with v = q̇. Then the system is linear:

ẋ = Ax,    A = [ 0   1 ;  −k/m  −c/m ] = [ 0   1 ;  −4  −0.4 ]   eigenvalues −0.2 ± 1.99i

Both eigenvalues are in the left half plane, so we already know the answer: it is stable, and the amplitude decays like e−0.2t. That is the point of choosing it. When a method produces a certificate we can check the certificate against the truth, and when a method produces a weak certificate we can measure exactly how much it gave away.

Part one

The basics

Lyapunov's idea, in one sentence: if some positive quantity strictly decreases along every trajectory, the trajectories have nowhere to go but the origin — and you can know that without ever solving the differential equation.

01

What we are trying to prove

Three statements, increasingly strong. They get confused constantly, so it is worth being precise about which one a certificate delivers.

stable
Start close enough to the origin and you stay close, forever. Nothing has to shrink. A frictionless pendulum swinging forever is stable.
asymptotically
stable
Stable, and trajectories starting near the origin actually converge to it.
exponentially
stable
Convergence at a guaranteed rate: ‖x(t)‖ ≤ M e−λt‖x(0)‖. This is the one engineers want, because it names a time constant.

Why not just simulate? Because a simulation settles one initial condition, and stability is a claim about all of them. Later it will be a claim about all initial conditions and every member of a family of systems at once — infinitely many infinities. Numerical experiments cannot close that; an inequality can.

For a linear system ẋ = Ax the eigenvalues answer the question outright: stable exactly when every eigenvalue has negative real part, which is what "Hurwitz" means. If that settles it, why does anyone need Lyapunov functions? Three reasons, all of which show up in this document: eigenvalues say nothing about nonlinear systems except very near an equilibrium; they say nothing about how large the transient gets on the way down; and — the big one — they say nothing at all about a system that switches or drifts between several matrices.

02

The direct method

Pick a scalar function V(x) and ask two things of it.

V(x) > 0 for x ≠ 0,  V(0) = 0
it measures "how wrong we are", and is zero only when we are right
V̇(x) < 0 for x ≠ 0
every instant of motion strictly reduces it, from every state

The derivative is taken along the motion, which is what makes this usable without solving anything. By the chain rule,

V̇(x) = (∂V/∂x) · ẋ = (∂V/∂x) · f(x)   no trajectory needed — just the vector field

If both conditions hold, the origin is asymptotically stable. The picture makes it obvious. The sets {x : V(x) = c} are nested shells around the origin; the first condition says they really do surround it; the second says the vector field points strictly inward everywhere on every shell. A trajectory can cross inward and can never cross back.

Two facts that follow from the picture, and are worth stating separately because they are what people actually use:

A sublevel set is an invariant region. If V̇ < 0 everywhere inside {V ≤ c}, no trajectory starting inside can ever leave. That is how Lyapunov functions produce guaranteed operating regions, not just yes-or-no answers.

A rate in V is a rate in x. Strengthen the second condition to V̇ ≤ −αV for some α > 0 and integration gives V(t) ≤ V(0)e−αt immediately. With a quadratic V this converts into a bound on the state itself, and the certificate becomes exponential rather than merely asymptotic. Every number called α in this document is that guaranteed rate.

03

The fine print

Three caveats. Each one has bitten someone.

1. Failing to find a V proves nothing. The conditions are sufficient, not necessary. If your candidate does not work, the system may still be perfectly stable — you have learned about your candidate, not about the system. (For the special cases in parts three and four there are converse theorems that close this gap; in general there is no such comfort.)

2. V̇ ≤ 0 is not V̇ < 0. A candidate that merely fails to increase proves stability, not convergence: the trajectory could park on a level set and orbit forever. This is not a technicality — it is exactly what the energy of our example does, and section 05 is about the two standard repairs.

3. Local unless proven otherwise. The conditions must hold on some region, and the conclusion holds only inside a sublevel set contained in that region. To claim global convergence you also need V to be radially unbounded (V(x) → ∞ as ‖x‖ → ∞) — otherwise trajectories can run off to infinity while sliding down a valley of V that never rises again. Quadratic V with P ≻ 0 is automatically radially unbounded, which is one more reason quadratics are popular.

The discrete-time twin Everything here has a sampled counterpart. For xk+1 = f(xk) the derivative is replaced by a difference, ΔV = V(xk+1) − V(xk) < 0, and for the linear case xk+1 = Adxk the condition ATP + PA ≺ 0 used below becomes AdTPAd − P ≺ 0. Same idea, same code, one substitution. Everything in this document is written in continuous time because the physics method needs it; the translation is mechanical.
Part two · method 1

Physics: use the energy

The oldest route, and still the first one to try. If the system stores and dissipates something — energy, heat, probability, money — that quantity is a Lyapunov candidate handed to you by the problem itself, and it usually works on the nonlinear model, not just a linearization.

04

The energy, and where it stalls

Our mass on a spring stores energy in two places: the spring, and the moving mass.

V(x) = ½kq² + ½mv²   spring + kinetic

It is positive for every non-zero state and zero only at rest at the origin, so the first Lyapunov condition holds for free. Now differentiate along the motion, using q̇ = v and mv̇ = −kq − cv:

V̇ = kq·q̇ + mv·v̇chain rule
   = kqv + v(−kq − cv)substitute the dynamics
   = −cv²the spring terms cancel

This is the whole physics of the thing in one line: the spring shuffles energy back and forth and never destroys any, and the damper burns it at a rate proportional to the square of the speed. It is also — read it again — not negative definite. When v = 0, V̇ = 0, no matter how far the mass is from centre. Those are the amber points in the figure of section 02: at the ends of each swing the energy stops falling.

In matrix form the candidate is V = xTPx with

P = [ k/2  0 ;  0  m/2 ] = [ 2  0 ;  0  0.5 ]     −(ATP + PA) = [ 0  0 ;  0  c ] = [ 0  0 ;  0  0.4 ]

and the failure is visible as an eigenvalue: that last matrix has eigenvalues 0 and 0.4. Semidefinite, not definite. By section 03's second caveat we have proved stability, and not convergence.

05

Two repairs, and what they cost

Repair 1: LaSalle's invariance principle. The classical fix, and it needs no new function. LaSalle says: if V̇ ≤ 0, trajectories converge to the largest invariant set inside {V̇ = 0}. Here {V̇ = 0} is the whole line v = 0. Can a trajectory stay on that line? If v ≡ 0 then v̇ ≡ 0 as well, and the dynamics force −kq = 0, so q = 0. The only invariant subset is the origin, so every trajectory converges to it. The energy was enough after all — with a second argument bolted on.

What LaSalle does not give you is a rate. The conclusion is asymptotic convergence, full stop. If you want exponential decay with a number attached, you need a candidate whose derivative is genuinely negative definite.

Repair 2: tilt the ellipse. Add a term that is not physical at all — a cross term between position and speed:

V = ½kq² + ½mv² + ε m q v,     P = [ k/2  εm/2 ;  εm/2  m/2 ]

Grinding through the same differentiation gives

V̇ = −(c − εm)v² − εk q² − εc qv

and now the q² term is there. The two conditions become two small algebraic requirements: V stays positive definite while ε < √(k/m) = 2, and V̇ is negative definite while ε is small enough that the v² term survives. With ε = 0.2,

P = [ 2  0.1 ;  0.1  0.5 ],     −(ATP + PA) = [ 0.8  0.04 ;  0.04  0.2 ] ≻ 0 ✓

Both conditions hold strictly, so this candidate proves exponential stability. The rate it certifies is the largest α with V̇ ≤ −αV, which for quadratics is the smallest generalized eigenvalue of the pair, α = λmin(M, P) with M = −(ATP + PA). Here it is 0.400000.

That number deserves a second look, because it is the best possible. The slowest mode of the system decays like e−0.2t, and V is quadratic in the state, so V cannot possibly decay faster than e−0.4t: no quadratic Lyapunov function can certify an α above 2|Re λ| = 0.4. A one-parameter guess, tuned by hand, hits the ceiling exactly.

The lesson worth carrying The physical energy is the right shape to within a small rotation, and that rotation is invisible to physics. Cross terms like qv are the standard trick, and the reason is structural: dissipation acts on v alone, so a certificate that only sees q² and v² cannot notice the spring quietly converting one into the other.
06

What the energy method is really for

On a linear example the energy method looks like a detour, since parts three and four will produce the same certificate mechanically. Its value is elsewhere.

It survives nonlinearity. Put the same damper on a pendulum, mL²θ̈ + cθ̇ + mgL sin θ = 0, and the energy still works, unchanged in spirit:

V = ½mL²θ̇² + mgL(1 − cos θ),     V̇ = −cθ̇²

No linearization, no small-angle assumption, and the level sets of V tell you directly how hard you can push the pendulum before it goes over the top — a genuine estimate of the region of attraction, which no eigenvalue can give you. The same two features appear again: the derivative is only semidefinite, and LaSalle finishes the argument.

It scales to systems you cannot write down cleanly. Circuits, mechanical linkages, thermodynamic systems, chemical reaction networks and network flows all come with a natural storage function, and the whole theory of passivity is built on using it as V. When a system is passive, interconnecting several of them adds their storage functions, and the sum is a Lyapunov function for the whole. That compositional property is something no matrix equation offers.

Where it stops. Three places. Some systems store nothing — a cycle-to-cycle model of a digital controller has no energy in it. When there is energy, its derivative is very often only semidefinite, so you always end up doing the extra work of section 05. And the energy tells you nothing about how much margin you have when the plant is uncertain: it is one function for one model. Hence the next two methods.

Part three · method 2

Quadratic forms: solve a matrix equation

Stop guessing the function and guess only its shape. Assume V = xTPx, and the two Lyapunov conditions turn into conditions on a matrix — which you can solve for.

07

The Lyapunov equation

Take V(x) = xTPx with P symmetric. The first condition, V > 0 away from the origin, is exactly P ≻ 0. For the second, differentiate along ẋ = Ax:

V̇ = ẋTPx + xTPẋproduct rule
   = (Ax)TPx + xTP(Ax)substitute the dynamics
   = xT(ATP + PA)xfactor

So "V̇ < 0 for all x ≠ 0" is the single matrix statement ATP + PA ≺ 0. Rather than search for a P that satisfies an inequality, pin the left side down to something you choose:

ATP + PA = −Q,    Q ≻ 0 chosen, P unknown

This is the Lyapunov equation, and it is linear in the unknown. Written out it is a system of n(n+1)/2 ordinary linear equations — three of them for our 2×2 example — with a unique solution whenever no two eigenvalues of A sum to zero, which every Hurwitz matrix satisfies. There is no search, no iteration, and no cleverness required. In MATLAB it is one call:

A = [0 1; -4 -0.4];
P = lyap(A', eye(2));          % solves A'*P + P*A + Q = 0
eig(P)                          % check P is positive definite
eig(A'*P + P*A)                 % check the decrease is definite
What Q means — this is the useful part The solution has a closed form, P = ∫0∞ eATt Q eAt dt, and therefore
V(x₀) = ∫0∞ x(t)TQ x(t) dt
Q is a price list — what you charge for error in each direction — and V(x₀) is the total bill the system will run up from x₀ until the end of time. Of course it decreases along the motion: each instant, some of the bill gets paid. Q = I means "charge for total squared deviation, equally in all directions", which is the default people type without thinking about it.

Every choice of Q ≻ 0 gives a valid P, so this method never fails on a stable linear system. That is not luck; it is a converse theorem. If A is Hurwitz, a quadratic Lyapunov function exists, and the integral above constructs it. Restricting attention to ellipsoids therefore costs nothing at all for linear systems — a guarantee that evaporates the moment the system is nonlinear or switches.

The one-line method that needs no insight is beaten, by a factor of two and a half, by the physicist's guess with one knob turned. That is not an argument against the Lyapunov equation — all three certificates are correct, and correctness is the point — but it is a precise statement of what the method costs you. You do not choose P, you choose Q, and the relationship between the Q you pick and the α you get is not something you can see in advance.

Two limits of this method follow directly, and both are what the next part exists to fix. It handles one matrix at a time — there is no version of lyap that takes two matrices and returns a P good for both, and no way to combine the two answers it gives you separately. And it optimizes nothing: you get the certificate that follows from your Q, not the best one available.

Part four · method 3

Optimization: let a solver find P

Both previous methods produce a certificate. This one produces the best certificate available, and — the reason it took over the field — it is the only one that can produce a single certificate valid for a whole family of systems at once.

09

The observation that makes it work

Go back to the two conditions and refuse to solve for P. Just look at them as they are, with P as the unknown:

P ≻ 0    and    ATP + PA ≺ 0

Both are linear in the entries of P. Neither has a square, a product of unknowns, or anything else awkward — A is data, P is the variable. A constraint of the form "this symmetric matrix, whose entries depend affinely on the unknowns, is negative definite" is called a linear matrix inequality, an LMI. Three consequences follow, and they are the whole reason for this part:

convex
The set of P satisfying an LMI is convex. There are no local minima to get stuck in, and a solver that says "infeasible" is making a claim it can prove, not giving up.
stackable
Two LMIs in the same unknown are just another LMI. Wanting one P to work for five different matrices costs you five constraints and nothing conceptually.
optimizable
You can minimize or maximize things over the feasible set — the decay rate, the size of an invariant ellipsoid, a disturbance gain — instead of accepting whatever falls out.

The practical form has two wrinkles worth knowing before you write any code. Solvers do not do strict inequalities, so P ≻ 0 is written P ⪰ I. That is not a restriction: the conditions are homogeneous — if P works then so does 10P — so any valid P can be scaled up until it dominates the identity. And a decay rate is imposed by a shift: replacing ATP + PA ⪯ 0 by

ATP + PA + αP ⪯ 0   ⟺  V̇ ≤ −αV  ⟺  V(t) ≤ V(0)e−αt

gives strictness for free whenever α > 0, and it is still an LMI — as long as α is a fixed number. If you make α a variable too, the term αP is a product of unknowns and the problem stops being convex. The standard fix is to bisect on α, solving a genuine LMI at each step. That is what the code below does.

10

Program one: the best certificate for one system

Set-up first. The code uses YALMIP, a modelling layer that turns MATLAB expressions into a solver's input format, together with any SDP solver — SeDuMi, SDPT3 and Mosek all work. Both are free downloads that you unzip and add to the path. The only two things to learn are sdpvar, which declares a matrix of unknowns, and optimize, which ships the constraint list off to the solver.

%% Program 1 — largest certifiable decay rate for a single system
A = [0 1; -4 -0.4];
opt = sdpsettings('solver','sedumi','verbose',0);

lo = 0; hi = 2; Pbest = [];              % alpha is known to lie in [0,2]
for it = 1:40
    al = (lo+hi)/2;

    P = sdpvar(2,2,'symmetric');         % 3 unknowns: p11, p12, p22
    C = [ P >= eye(2) , ...                % P positive definite (scaled)
          A'*P + P*A + al*P <= 0 ];        % V-dot <= -alpha V

    d = optimize(C, [], opt);              % no objective: pure feasibility

    if d.problem == 0                      % 0 = solved, 1 = infeasible
        lo = al; Pbest = value(P);          % alpha achievable, try higher
    else
        hi = al;                           % not achievable, back off
    end
end

alpha_max = lo
P = Pbest / trace(Pbest)                   % fix the free scale, for readability

Running it returns

αmax = 0.399999,     P = [ 0.8  0.04 ;  0.04  0.2 ]

Two things to notice. The rate matches the theoretical ceiling 2|Re λ| = 0.4 to six digits — the solver found the best quadratic certificate that exists, without being told anything about eigenvalues. And compare that P with the hand-tilted energy of section 05, [2  0.1 ; 0.1  0.5]: it is the same matrix, scaled by 0.4. The optimizer rediscovered the physicist's guess and proved that nothing beats it.

Reading the solver's answer d.problem is the status code: 0 solved, 1 infeasible, 2 unbounded, 4 numerical trouble. Never trust value(P) without checking it. And always verify the result outside the solver — two lines that cost nothing and catch scaling disasters: 
eig(P)                      % must all be > 0
eig(A'*P + P*A + alpha_max*P)   % must all be <= 0 (up to solver tolerance)
11

Program two: one V for a whole family

Now the thing neither of the earlier methods can do. Suppose the damping is not known exactly — a friction coefficient that changes with temperature, wear, or how long the machine has been running:

c ∈ [0.2, 1.2],     A(c) = [ 0   1 ;  −4  −c ]   a continuum of systems

We want one V that decreases for every value of c in that interval, including a c that drifts while the system runs. Infinitely many constraints — except that they collapse to two, and the reason is worth a moment.

Why the two extremes are enough

Write any intermediate system as a blend of the extremes, A(c) = (1−θ)Alo + θAhi with θ ∈ [0,1] — which works here because A depends affinely on c. The Lyapunov expression is linear in A, so

A(c)TP + PA(c) = (1−θ)(AloTP + PAlo) + θ(AhiTP + PAhi)

A weighted average of two negative definite matrices, with non-negative weights, is negative definite. So satisfying the LMI at the two endpoints satisfies it everywhere in between, automatically. Two constraints buy a continuum.

The same argument covers any polytopic family: several uncertain parameters give a box with 2p corners, and you write one constraint per corner. It also covers arbitrarily fast variation, because nothing in the argument assumed c was constant — the certificate is a statement about the vector field at each instant, whatever the parameter is doing.

%% Program 2 — one V for the whole damping range
mk = @(k,c) [0 1; -k -c];
F  = { mk(4, 0.2), mk(4, 1.2) };           % the two vertices
opt = sdpsettings('solver','sedumi','verbose',0);

lo = 0; hi = 3; Pc = [];
for it = 1:45
    al = (lo+hi)/2;
    P  = sdpvar(2,2,'symmetric');
    C  = [ P >= eye(2) ];
    for i = 1:numel(F)                     % one LMI per vertex, same P
        C = [ C , F{i}'*P + P*F{i} + al*P <= 0 ];
    end
    d = optimize(C, [], opt);
    if d.problem == 0, lo = al; Pc = value(P); else, hi = al; end
end

alpha_robust = lo
P = Pc / trace(Pc)

% verify on the vertices AND on interior points the solver never saw
for c = [0.2 0.45 0.7 0.95 1.2]
    Ai = mk(4,c);
    fprintf('c=%.2f  eig = %s', c, mat2str(eig(Ai'*P + P*Ai)',4));
end

The result:

αrobust = 0.199370,     P = [ 0.8  0.0201 ;  0.0201  0.2 ]

and the verification loop reports negative definiteness at every interior c, exactly as the proposition promised. Read the number: the worst member of the family is c = 0.2, whose own true rate is 2|Re λ| = 0.2. The single certificate that covers the entire range gives up only 0.3 % against the best that could ever be claimed for its weakest member. Note also the shape — the same [0.8, ·; ·, 0.2] diagonal as the nominal answer, with the tilt reduced from 0.04 to 0.02. The robust ruler is the nominal one, straightened up a little to accommodate both extremes.

You cannot patch this by hand Solving the Lyapunov equation at c = 0.2 gives a P that happens to also work at c = 1.2; solving it at c = 1.2 gives one that does not work at c = 0.2. Same method, same family, opposite outcomes, no way to tell in advance. Averaging the two solutions is not a fix either — there is no theorem behind it. The LMI is not a fancier way of doing the same thing; it is the only way to ask for what you actually want.
12

When there is no such V

Change what is uncertain. Keep the damping fixed at c = 0.4 and let the stiffness switch between two values, k = 4 and k = 9 — a spring that engages a second stage, or a contact that stiffens. Both modes are Hurwitz, and each is a perfectly well-behaved damped oscillator. Ask for a common V:

F = { mk(4,0.4), mk(9,0.4) };
P = sdpvar(2,2,'symmetric');
d = optimize([P >= eye(2), F{1}'*P+P*F{1} <= 0, F{2}'*P+P*F{2} <= 0], [], opt);
d.problem     %  → 1
d.info        %  → 'Infeasible problem (SeDuMi)'

There is no common quadratic Lyapunov function. And this time the solver is not being fastidious — the switched system really can be driven unstable, by a rule any child on a swing discovers independently: stiffen while swinging toward the centre, soften while swinging away.

How far apart can the two stiffnesses be before the certificate dies? Bisecting on the second stiffness with k₁ = 4 and c = 0.4, a common quadratic exists up to k₂ = 5.76 — a stiffness ratio of 1.44 — and not beyond. That number is not a rule of thumb you could have guessed; it fell out of the same three lines of code.

What infeasibility does and does not mean It means no single ellipsoid certifies the whole family. It does not by itself mean the switched system is unstable — that had to be demonstrated separately, with the simulation above. Plenty of stable switched systems admit no common quadratic; for those you need a richer certificate, not a different conclusion.

The standard escalations, in rough order of effort:

dwell-time
conditions
if the system cannot switch too often, each mode's own V can be used, provided the jumps between them are accounted for — this is often the practical answer, since real machines do not switch arbitrarily fast
multiple
Lyapunov functions
one Pi per mode, with matching conditions at the switching instants
piecewise
quadratic
a different ellipsoid in each region of the state space, glued together where they meet
polyhedral
V(x) = ‖Wx‖∞, level sets are polytopes; one always exists for a stable switched linear system, but it may need very many faces
sum of squares
polynomial V of degree 4, 6, … found by a larger semidefinite program; quadratics are the degree-2 corner of this
The same machinery designs controllers Everything above only analyses a given system, but the LMI form does more. For ẋ = Ax + Bu with u = Kx, the condition (A+BK)TP + P(A+BK) ≺ 0 has a product of two unknowns and is not an LMI — until you substitute W = P−1 and Y = KW, multiply left and right by W, and get AW + WAT + BY + YTBT ≺ 0, which is linear in (W, Y). Solve it, recover K = YW−1, and you have a controller and its stability proof from one convex program — for the whole uncertain family at once, if you write one constraint per vertex. That change of variables is why LMIs took over robust control in the 1990s.

A working recipe 1. Write down every system the loop can actually be — one matrix if it is fixed, a list of vertices if parameters vary or modes switch. 2. If there is exactly one and it is linear, call lyap and stop; you have a certificate in a second. 3. If the model is nonlinear and stores something physical, try that quantity first, and expect to need LaSalle or a cross term. 4. If there is more than one system, or you need the rate to be as tight as possible, write the LMI — one constraint per vertex, one shared P, bisect on α. 5. Verify outside the solver, on points it never saw. 6. If it comes back infeasible, ask whether the switching is really arbitrary before reaching for a richer V; a dwell-time bound is often both true and enough.

  9. The solver returns infeasible. What have you learned about the system — and what have you not? (12)
  10. Both modes of a switched system are stable, and it diverges. Explain to a colleague how that is possible. (12)

One example throughout: a mass–spring–damper with m = 1, k = 4, c = 0.4. Every number quoted was computed — trajectories by fourth-order Runge–Kutta, P matrices by lyap and by SeDuMi through YALMIP, and each certificate checked afterwards by eigenvalue tests outside the solver. The MATLAB in sections 10 to 12 is the code that produced the results shown beside it.
